Profile — match review & replay

Every row under Recent becomes tappable. A Battle Table match opens a chess.com-style replay: step through each placement, spell, trap and ability with the board redrawn at that moment, an HP swing graph you can scrub, and a move list that jumps anywhere. Matches recorded before board snapshots existed fall back to a turn-grouped log (what the server stores today). A Siege run opens a route summary drawn as the expedition map, with the path taken lit and each stop tappable. All frames are live with sample data — open this page on a phone for a full-bleed version with a switcher, or add ?screen=recent|replay|log|siege|ledger.

1 · Profile › Recent

Rows gain a chevron and a “Replay” / “Log” / “Route” hint so it is obvious what a tap opens. Siege runs join the list with their own badge. Tap a row.

2 · Battle replay

◀ ▶ step one action, ⏮ ⏭ jump by turn, ▶ autoplays. Tap the HP graph or any move to jump. Arrows show who acted on whom; ★ marks turning points.

3 · Log-only review

For older matches (and online matches until snapshots ship): the stored gameLog grouped into collapsible turns with phase chips and key lines lifted.

4 · Siege run summary

Each stop on the route is captioned on the map. Tap a stop for its detail: enemy warbands and who fell, card picks, Broker purchases, Caravan trades, Smith upgrades, event choices and rest healing.

5 · Siege run ledger

The same run as a scrolling timeline: every stop in order with who was fought, what was bought, sold, traded or upgraded, and the running gold balance.

What exists today

  • MatchHistoryEntity stores result, opponent, turns, HP left, spells/traps/defeats and gameLog — enough for frame 3.
  • GameState.gameLog is trimmed to the last 80 lines once it passes 100, so long matches lose their opening turns.
  • openMatchReview in home.js already renders a flat log; the redesigned hub’s Recent rows are not tappable.
  • Siege runs are not written to match history at all.

What replay needs (backend)

  • A compact replay list on the history doc: one entry per action — turn, phase, actor/target cells, log line, and a board snapshot (cell → card id, HP, status) plus both HP totals.
  • ~40–80 steps × ~18 cells stays well under Firestore’s 1 MB doc limit; store only diffs if it grows.
  • Stop truncating the log for the recorded copy (keep the full list server-side even if the live state trims).
  • Online matches: record from each side’s view so hidden cards (face-down traps, hand) are never leaked.

What Siege needs

  • On run end, write a siegeRunHistory doc: knight, warband, outcome, floor reached, the map layout (node ids, types, edges) and the ordered path. Each path entry carries the stop’s land and title, gold delta, and a typed payload: battle (enemy ids + HP left, your fallen, turns, items used, card offered/picked), broker (bought/sold item ids + prices, items passed on), caravan (gave/got), smith (card, move, stat before/after), event (choice taken + outcome), rest (HP before/after, revives).
  • Surface it in matchHistory responses with matchType: "SIEGE" so Recent needs no second fetch.
